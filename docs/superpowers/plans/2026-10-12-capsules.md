# Capsules : plan d'implémentation

Spécification : `docs/superpowers/specs/2026-10-12-capsules-design.md`.

Sept étapes, dans cet ordre. Chacune se termine par `scripts/ci.sh` propre et
un commit ; le dépôt compile et ses tests passent après chaque étape. Pour le
modèle et la géométrie, les tests sont écrits avant le code.

Entre l'étape 3 et l'étape 5, la bande au-dessus des emplacements est
réservée mais vide : les onglets ne sont plus dans les barres et pas encore
en capsules. `Mod+Page suiv./préc.` fonctionne pendant ce temps.

## Décisions de détail prises en écrivant ce plan

- **Boutons au survol sans changement de largeur.** Une capsule qui
  s'élargirait au survol déplacerait tout le groupe (il est centré) sous le
  pointeur. *Révisé à l'étape 6* : faire recouvrir la fin du nom par les
  boutons s'est révélé dangereux (un clic sur le nom fermait la fenêtre).
  Toutes les capsules réservent la place de leurs boutons ; une capsule de
  moins de 72 px n'en a pas.
- **« Au centre » crée une habitude**, comme « Ranger ici » : c'est un
  rangement fait par l'utilisateur (règle 4). L'échange, lui, n'en créait pas.
- **Nom affiché** : celui de l'appli (`ManagedWindow::name`), pas le titre de
  la fenêtre.
- **Ordre de dessin** : les groupes ne recouvrent jamais une fenêtre rangée ;
  ils sont dessinés sous toutes les fenêtres, au-dessus du fond et des
  panneaux `Bottom` et `Background`.

## Étape 4 — Géométrie des capsules

Fichiers : `crates/compositor/src/decoration/capsules.rs` (nouveau),
`crates/compositor/src/decoration/mod.rs`.

Géométrie pure, tests d'abord, sur le modèle de `decoration/layout.rs`.

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum CapsuleButton {
    Minimize,
    Close,
}

/// What a capsule asks for.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct CapsuleWish {
    /// Width of its label, as the painter measures it.
    pub label_width: i32,
    /// It shows its window: its buttons have their own room.
    pub shown: bool,
}

/// Rectangles relative to the band's top-left corner.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct CapsuleCell {
    pub rect: Rect,
    pub icon: Rect,
    pub label: Rect,
    /// Left to right; empty when the capsule is too narrow.
    pub buttons: Vec<(CapsuleButton, Rect)>,
}

#[derive(Debug, Clone, Default, PartialEq, Eq)]
pub struct GroupLayout {
    pub rect: Rect,
    pub capsules: Vec<CapsuleCell>,
}

impl GroupLayout {
    pub fn new(band: Size, wishes: &[CapsuleWish]) -> Self;
    pub fn capsule_at(&self, point: Point) -> Option<usize>;
    pub fn button_at(&self, point: Point) -> Option<(usize, CapsuleButton)>;
}
```

Constantes : marge du groupe 3, écart entre capsules 2, marge d'une capsule
10, icône 14, écart icône-nom 6, bouton 20, largeur maximale 200, largeur
minimale 34 (icône seule), seuil des boutons 64.

Tests :

- un groupe d'une capsule est centré dans la bande, haut de 32 px ;
- une capsule ne dépasse pas 200 px ;
- la capsule affichée réserve 40 px pour ses boutons, les autres non ;
- les boutons d'une capsule non affichée recouvrent la fin de son nom, et sa
  largeur est la même qu'avec `shown: false` sans survol ;
- un groupe trop large rétrécit toutes les capsules ensemble, jamais sous
  34 px, et ne dépasse pas la bande tant que c'est possible ;
- une capsule de moins de 64 px n'a pas de bouton ;
- `capsule_at` et `button_at` : sur une capsule, sur un bouton, entre deux
  capsules, hors du groupe ;
- aucune capsule, ou une bande de largeur nulle : rien, pas de largeur
  négative.

Commit : `Lay out the capsules of a slot`.

## Étape 5 — Dessiner les capsules

Fichiers : `crates/compositor/src/decoration/paint.rs`,
`crates/compositor/src/{shell,state}.rs`,
`crates/compositor/src/render/scene.rs`.

Avant d'écrire : relire `MemoryRenderBuffer` et
`MemoryRenderBufferRenderElement` dans la documentation de la version de
Smithay épinglée (`cargo doc -p smithay`), comme le fait déjà le code des
barres de titre.

1. `paint.rs` :

   ```rust
   /// Everything the look of a group depends on.
   #[derive(Debug, Clone, PartialEq, Eq)]
   pub struct GroupSpec {
       /// Size of the band.
       pub size: Size,
       pub capsules: Vec<CapsuleSpec>,
       /// The capsule under the pointer, and its button there if any.
       pub hovered: Option<(usize, Option<CapsuleButton>)>,
       pub theme: ThemeKind,
       pub accent: Rgba,
   }

   #[derive(Debug, Clone, PartialEq, Eq)]
   pub struct CapsuleSpec {
       pub label: String,
       pub icon: Option<String>,
       pub badge: [u8; 3],
       pub shown: bool,
       pub focused: bool,
       pub minimized: bool,
   }
   ```

   `Painter::capsule_group(&mut self, spec) -> Option<(Pixmap, GroupLayout)>`
   mesure les noms (`cosmic-text`, même police que les barres, 12 px),
   calcule le `GroupLayout`, puis peint dans une image de la taille de la
   bande, transparente hors du groupe : fond du groupe (`titlebar` à 85 %,
   rayon 16), capsule affichée (`button_hover`, rayon 13), anneau d'accent de
   2 px si `focused`, icône (`app_mark`), nom, boutons de la capsule affichée
   et de la capsule survolée (survol : `button_hover`, `close_hover`).
2. `shell.rs` : `Shell::capsules: Vec<CapsuleGroupView>`.

   ```rust
   /// The capsules of one slot, as drawn.
   pub struct CapsuleGroupView {
       pub group: CapsuleGroup,
       /// Top-left corner of its screen in the global space.
       pub origin: ModelPoint,
       /// Where things ended up at the last paint; empty before it.
       pub layout: GroupLayout,
       spec: Option<GroupSpec>,
       buffer: Option<MemoryRenderBuffer>,
   }
   ```

   `sync` reconstruit la liste depuis `desk.capsule_groups()` en gardant la
   texture des groupes dont le `SlotId` n'a pas changé. `refresh_chrome`
   reçoit le survol des capsules, construit chaque `GroupSpec` et ne repeint
   que ceux qui ont changé.
3. `state.rs` : `capsule_hover: Option<(SlotId, usize, Option<CapsuleButton>)>`,
   à `None` pour l'instant.
4. `scene.rs` : un élément de texture par groupe, à la position de sa bande
   (avec le même décalage `shift` que les fenêtres), placé après toutes les
   fenêtres et avant les panneaux `Bottom` et `Background`.
5. Essai en imbriqué, captures relues en clair et en sombre :
   `--three-screens`, deux kitty et `gnome-calculator` rangés à gauche dans
   le même emplacement, un kitty seul dans l'autre. Attendu : deux groupes
   centrés, capsule affichée pleine avec ses deux boutons, anneau d'accent
   sur celle de la fenêtre active, pas de barre du shell sur la calculatrice.

Commit : `Draw the capsules above each slot`.

## Étape 6 — La souris sur les capsules

Fichiers : `crates/compositor/src/{input,state}.rs`.

1. `Hit` : `capsule: Option<(SlotId, usize, Option<CapsuleButton>)>`.
   Dans `hit_test`, après la boucle des fenêtres et avant les panneaux du
   bas : pour chaque `CapsuleGroupView`, point ramené au coin de la bande,
   puis `layout.capsule_at` et `layout.button_at`. Un bouton d'une capsule
   non affichée ne compte que si elle est assez large pour en avoir (c'est
   le `GroupLayout` qui le dit).
2. `pointer_moved` : `capsule_hover` suit `hit.capsule` ; le curseur est
   celui par défaut au-dessus d'un groupe.
3. Nouveau geste :

   ```rust
   /// Down on a capsule, not moved yet: a click, or the start of a drag.
   CapsulePressed {
       slot: SlotId,
       index: usize,
       window: WindowId,
       at: Point<f64, Logical>,
       button: Option<CapsuleButton>,
   },
   ```

   - `start_gesture` : un appui sur une capsule le démarre et garde l'appui
     pour le shell ; avec `Mod`, la séparation garde la priorité.
   - `advance_gesture` : sans bouton, au-delà de `DRAG_THRESHOLD`, il devient
     `Gesture::Placing { window }`.
   - relâchement : sur le bouton où l'appui a commencé, `minimize_window` ou
     `close_window` ; sinon `desk.activate_tab(slot, index)` puis
     `apply_arrangement` (ce qui ramène aussi une fenêtre réduite).
4. Un clic sur une capsule rend le clavier aux fenêtres s'il était à un
   panneau `OnDemand`, comme un clic sur une fenêtre.
5. Essais scriptés (`--debug-input`, syntaxe dans
   `crates/compositor/src/debug.rs`), captures relues :
   - clic sur une capsule non affichée : sa fenêtre s'affiche et a l'anneau ;
   - survol d'une capsule non affichée : ses boutons apparaissent, le groupe
     ne bouge pas ;
   - bouton réduire : capsule grisée ; clic dessus : fenêtre revenue ;
   - réduire la seule fenêtre d'un emplacement : le groupe reste ;
   - bouton fermer sur une capsule non affichée : elle disparaît, la fenêtre
     affichée ne change pas ;
   - glisser une capsule vers l'écran du centre : zones affichées, fenêtre
     rangée au relâchement ;
   - `Mod+glisser` sur la séparation : les groupes suivent ;
   - `kitty --start-as fullscreen` sur l'écran : plus de capsules ;
   - « Au centre » depuis la barre de rangement.

Commit : `Click, drag and close windows from their capsule`.
